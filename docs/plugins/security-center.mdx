## 概述

Rainbond 安全中心插件面向平台管理员、运维人员和组件负责人，统一展示平台与组件的安全状态。启用后，可以在平台管理视图查看全局安全态势、团队风险和问题清单，也可以进入组件视图查看单个组件的镜像风险、运行配置和网络隔离状态。

安全中心提供两个主要入口：

| 视图入口 | 适用对象 | 主要能力 |
| :--- | :--- | :--- |
| **平台管理 -> 安全中心** | 平台管理员、运维人员 | 查看环境安全状态、严重与高危问题、团队风险汇总、安全问题清单和历史扫描 |
| **组件视图 -> 安全中心** | 开发者、组件负责人 | 查看当前组件的镜像与运行安全报告，重新检测当前组件，配置网络隔离和运行安全参数 |

## 功能对比

| 维度 | 开源版 | 安全中心插件 |
| :--- | :--- | :--- |
| **安全视图** | 缺少统一的安全态势入口 | 提供平台、团队和组件多层级安全视图 |
| **镜像风险** | 需要使用外部工具逐个检查 | 集中展示镜像漏洞、影响软件包、风险级别和修复版本 |
| **运行风险** | 依赖人工检查工作负载配置 | 自动汇总运行配置、权限、敏感信息和暴露面问题 |
| **问题定位** | 需要手动查找受影响组件和资源 | 展示受影响团队、资源类型和资源对象，并支持下钻处理 |
| **网络隔离** | 需要手动维护 Kubernetes 网络策略 | 在组件视图配置访问白名单，并可根据组件依赖同步规则 |
| **报告管理** | 无统一历史记录和导出入口 | 支持全局扫描、组件检测、历史扫描和报告导出 |

## 核心能力

### 平台安全态势

平台管理中的「安全中心」提供统一的环境安全视图，根据严重与高危问题综合判断当前环境状态，并展示影响团队数量和不同安全域的风险概况。

![安全中心平台概览](/plugins/security-center/security-center-overview.png)

安全态势由以下四个方面组成：

| 安全域 | 说明 |
| :--- | :--- |
| **镜像安全** | 统计业务镜像和基础镜像中的漏洞，展示严重、高危、中危和低危问题数量 |
| **运行安全** | 检查工作负载配置、权限控制、敏感信息、资源限制和服务暴露面 |
| **网络安全** | 统计网络隔离策略及策略覆盖情况，帮助识别未配置访问边界的组件 |
| **访问配置** | 检查登录验证码、注册验证码、找回密码验证码和登录限制的启用情况 |

### 团队汇总与问题定位

团队安全汇总按照问题数量展示各团队的风险分布、影响镜像和影响资源，便于平台管理员快速识别需要优先处理的团队。

安全问题清单支持按照团队、风险等级和问题类型筛选，也可以通过关键字搜索漏洞或检查项。展开问题后，可以查看命中的团队、资源类型、资源对象和镜像，并进入对应组件继续处理；没有对应 Rainbond 组件的工作负载，可进入团队的 Kubernetes 原生资源视图查看。

![安全问题影响资源](/plugins/security-center/security-center-issue-resources.png)

### 镜像安全

镜像安全报告展示当前镜像中的漏洞及修复信息，包括：

* CVE 编号和风险等级
* 受影响的软件包和已安装版本
* 可用的修复版本和处理建议
* 影响镜像、影响资源及资源数量
* 扫描镜像与组件实际运行镜像的一致性

当扫描镜像与实际运行镜像不一致时，页面会显示提示。此时应以组件当前运行镜像为准重新核验，避免依据旧镜像报告进行处置。

### 运行安全

运行安全报告检查组件的工作负载配置和权限边界，覆盖资源限制、健康检测、特权模式、根用户、文件系统、主机目录、端口、网络模式、Seccomp 和容器能力等常见风险。

对于可以在 Rainbond 中直接处理的问题，报告会提供对应的处理入口，例如手动伸缩、健康检测、存储设置、端口设置、构建源或其他设置。组件负责人可以根据建议进入相应配置页面完成整改。

### 组件网络隔离

组件视图支持配置组件间访问控制：

* **收紧策略**：仅允许白名单中的组件访问当前组件，或允许当前组件访问白名单中的目标
* **临时放开**：暂时关闭白名单限制，按现有网络连通性访问
* **入站规则**：控制哪些组件可以访问当前组件
* **出站规则**：控制当前组件可以访问哪些组件
* **同步组件依赖**：根据 Rainbond 组件依赖关系生成对应访问规则

### 全局扫描与组件检测

平台管理员可以在平台安全中心点击 **全局扫描**，重新生成当前可见团队范围内的安全报告。组件负责人也可以在组件安全中心点击 **重新检测**，仅重新检测当前命名空间中的当前组件。

组件级检测通过命名空间、组件标识和组件别名精确匹配，不会删除或重新生成其他组件的报告。一个组件包含多个容器时，可能产生多个镜像检测任务，但这些任务仍属于同一个组件。

扫描过程中页面会持续展示状态。团队范围内的扫描任务结束后，安全中心会等待报告连续稳定，再自动切换为完成状态并刷新数据。后端会独立跟踪扫描进度，不依赖浏览器页面是否保持在前台。

### 历史扫描与报告导出

* **历史扫描**：查看历史扫描时间、状态、安全评分和各风险等级数量
* **导出报告**：导出当前安全报告，便于离线分析、整改跟踪和安全审计
* **基础配置**：统一查看和调整验证码及登录限制配置

## 使用指南

### 启用插件

1. 进入 **平台管理 -> 功能扩展**。
2. 找到「安全中心」插件并安装或启用。
3. 安装完成后刷新页面，平台管理视图左侧会出现「安全中心」入口，组件视图中也会出现「安全中心」标签页。

:::info 首次安装
安全中心首次安装后会自动为业务团队中的现有工作负载生成报告。此时可能在插件命名空间中看到名称以 `scan-vulnerabilityreport-` 开头的临时 Pod。这些 Pod 用于生成镜像安全报告，执行完成后会退出，不代表业务组件异常。

默认不会扫描 Rainbond 和 Kubernetes 的系统命名空间，扫描时间主要取决于业务组件数量、镜像大小和镜像仓库访问速度。
:::

### 查看平台安全报告

1. 进入 **平台管理 -> 安全中心**。
2. 查看环境安全状态、严重问题、高危问题和影响团队数量。
3. 查看镜像安全、运行安全、网络安全和访问配置四个安全域。
4. 在团队安全汇总中选择目标团队，或在安全问题清单中筛选需要处理的问题。
5. 展开问题查看影响资源，点击 **详情** 进入对应组件或 Kubernetes 原生资源。

### 执行全局扫描

1. 在平台安全中心点击 **全局扫描**。
2. 等待团队范围内的临时扫描任务完成。
3. 报告稳定后，页面会自动结束扫描状态并加载最新结果。
4. 如需保留结果，点击 **导出报告**；如需回溯，点击 **历史扫描**。

### 查看并重新检测组件

1. 进入目标应用并选择需要检查的组件。
2. 在组件详情中切换到 **安全中心** 标签页。
3. 查看镜像安全、运行安全和网络隔离摘要。
4. 在详细检测报告中切换 **镜像安全** 或 **运行安全** 页签。
5. 点击 **重新检测** 时，仅会重新生成当前组件的报告。

### 配置组件网络隔离

1. 在组件安全中心展开 **配置 -> 网络策略配置**。
2. 开启收紧策略。
3. 根据访问方向添加入站或出站白名单规则。
4. 如组件已经配置依赖关系，可同步依赖生成访问规则。
5. 保存后确认组件间访问正常。

## 状态说明

| 状态 | 说明 |
| :--- | :--- |
| **扫描中 / 检测中** | 临时扫描任务仍在运行，或者报告正在完成最终同步 |
| **已完成** | 扫描任务已结束，报告已经稳定并加载 |
| **未检测 / 无报告** | 当前资源尚未匹配到对应报告，不能据此判定为安全 |
| **正常** | 已有对应检测报告，并且当前检测范围内没有发现问题 |
| **存在风险 / 需处理** | 已发现安全问题，应根据风险等级和修复建议处理 |

:::warning 注意
「未检测」不等于「安全」。如果组件没有镜像安全或运行安全报告，请先执行重新检测，并确认镜像仓库可访问、组件标识匹配且临时扫描任务执行成功。
:::
