# 多集群应用统一管理

**版本基线：** Rainbond 6.x。多集群应用管理不等于自动实现跨集群网络和数据库容灾。

## 操作步骤

1. 记录每个集群的 Kubernetes 版本、节点架构、存储类、入口 IP、DNS 和网络限制。
2. 在平台管理端接入或安装集群，等待节点与核心组件健康。
3. 建立开发、测试、生产团队与权限边界，不让业务成员持有集群管理员凭据。
4. 在开发集群验证应用，将拓扑发布为模板或复制到测试集群。
5. 为目标集群分别设置存储、域名、外部数据库和环境变量。
6. 生产升级前在同构测试集群验证；按集群分批发布并保留回滚版本。

## 验证与排错

```bash
kubectl version
kubectl get nodes -o wide
kubectl get storageclass
```

- 集群离线：检查管理端与集群端组件的网络、证书和时间同步。
- 应用复制后存储失败：目标集群不存在同名存储类时重新选择可用存储。
- 域名冲突：每个集群使用独立入口域名或明确的全局流量策略。
- 数据不一致：数据库复制、备份与容灾由数据库方案负责。

能力说明见 [Kubernetes 多集群管理](/feature/multi-cluster)。
