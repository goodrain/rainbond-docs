# 企业内部应用市场建设

**版本基线：** Rainbond 6.x。内部市场用于沉淀可安装、可升级的技术资产，不替代代码仓库、采购审批、合同或许可证管理。

## 最小模板规范

- 清晰的业务名称、版本、负责人和适用环境。
- 组件、端口、依赖、存储和健康检查完整。
- 环境差异参数化；密钥在安装时注入，不固化在模板。
- 安装验证、数据初始化、升级、回滚和已知限制说明。

## 操作步骤

1. 选择已在真实环境运行的应用，不把未验证 Demo 直接发布为企业模板。
2. 清理固定 IP、测试密码和客户专属域名，改为安装参数。
3. 在干净团队安装一次，确认不依赖源环境的隐藏状态。
4. 发布模板版本并设置可见范围，记录变更和兼容条件。
5. 由使用团队从市场安装，完成验收后记录反馈。
6. 新版本先在测试环境升级，核对属性合并和数据库迁移。

## 常见故障

- 安装后仍访问源数据库：模板中残留固定地址，应改为参数或组件依赖。
- 升级未覆盖变量：部分环境变量按规则只新增，现场值需人工确认。
- 删除组件不生效：模板升级对删除操作有保护，按升级规则处理。
- 模板无法跨集群：检查目标镜像仓库、CPU 架构、存储类和外部依赖。
