# 应用模板导出、导入、升级和回滚

**版本基线：** Rainbond 6.x。模板包含组件与主要运行属性，但不应包含生产密钥，也不自动携带数据库业务数据。

## 操作步骤

1. 在源环境确认所有组件健康、端口和依赖正确，并记录业务版本。
2. 进入应用发布流程，选择组件，填写模板版本、更新说明和安装参数。
3. 发布到团队或企业应用市场；离线交付时导出应用包。
4. 在目标环境导入，按实际存储类、域名、镜像仓库和数据库填写参数。
5. 安装后执行健康检查、接口测试、重启测试和数据校验。
6. 新版本先在验收环境升级；核对属性差异后再进入生产。
7. 运行异常时在组件版本记录中回滚；数据库回滚按业务迁移方案执行。

## 升级必须检查

| 属性 | 风险 |
| --- | --- |
| 镜像与启动命令 | 新版本通常会更新 |
| 环境变量 | 部分规则只新增，不覆盖现场值 |
| 存储 | 不等于数据备份，升级前仍需备份 |
| 配置文件 | 内容可能更新，路径和名称有独立规则 |
| 组件删除 | 模板删除不一定自动删除目标组件 |

详细合并行为见 [应用升级属性变更规则](/docs/how-to-guides/delivery/upgrade-app) 和 [应用模型参数](/docs/how-to-guides/delivery/app-model-parameters)。
